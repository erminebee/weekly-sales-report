# 주간 매출 리포트 (weekly-sales-report)

구글 시트 '판매관리'의 판매내역으로 지난주(월~일) 매출 리포트를 만들어 슬랙 채널에 올린다.

## 고정 규칙 (사용자가 정한 것)
1. 채널에는 헤더 한 줄만 보낸다: `[주간 매출 리포트] M/D(월)~M/D(일)` (예: `[주간 매출 리포트] 10/19(월)~10/25(일)`). 리포트 내용은 모두 그 메시지의 **스레드**에 단다.
2. 보내기 전에 채널을 읽어 **같은 첫 줄의 메시지가 이미 있으면 아무것도 보내지 않고** 사용자에게 알린다.
3. 만들기 전에 아래 "확인할 기준"을 사용자에게 먼저 묻는다. 사용자가 요청에서 이미 정한 항목은 다시 묻지 않는다. 묻기 전에 시트 구조 확인 같은 읽기 작업은 해도 된다.
4. 기본 채널은 `#주간리포트-테스트`다. 다른 채널을 말하면 그 채널을 쓴다. 채널 ID는 슬랙 채널 검색으로 확인한다.

## 확인할 기준 (AskUserQuestion으로 한 번에 묻기)
- **데이터 시트**: 같은 이름 '판매관리' 시트가 여러 개일 수 있다. Drive 검색 결과(소유자, 생성일, 수정일)를 보여주고 고르게 한다.
- **매출 기준**: 결제금액 합계 / 결제금액+배송비 별도 표기 / 결제금액에서 배송비 제외.
- **구성 항목** (복수 선택): 총매출·주문 수·객단가, 판매채널별, 카테고리별, 상품별 TOP 5(매출 또는 수량 기준).
- **비교 기준**: 전주 / 전주+전년 동기 / 비교 없음.

지난번 선택값(제안 기본값으로만 사용): 총매출·주문 수·객단가, 판매채널별, 카테고리별, 상품 TOP 5(매출 기준), 전주+전년 동기 비교.

## 시트 구조 (판매관리)
- 탭: `판매내역`(원본), `대시보드`(요약).
- `판매내역` 열: 주문일, 주문번호, 판매채널, 카테고리, 상품명, 옵션, 수량, 판매단가, 결제금액, 배송비. 숫자는 `33,300`처럼 쉼표가 들어간 문자열이다.
- 행은 주문일 순으로 정렬돼 있고 시트의 행 수(rowCount)는 실제 데이터보다 크다(빈 행 포함).
- 한 주문번호가 여러 행(상품 줄)일 수 있다. **주문 수는 주문번호 중복 제거 기준**으로 센다.
- `결제금액 = 판매단가 × 수량`이고 배송비는 결제금액에 포함되지 않는다(배송비가 있는 행도 동일). 대시보드의 총 매출도 결제금액 합계이고 배송비 합계는 따로 표시한다. 따라서 "배송비 제외 매출"은 결제금액 합계 그대로이며, 배송비를 한 번 더 빼면 안 된다. 사용자가 "결제금액에서 배송비 제외"를 골랐더라도 이 점을 확인해 결제금액을 그대로 쓰고, 최종 답변에서 한 줄로 알린 뒤 원하면 배송비를 뺀 값으로 다시 올리겠다고 제안한다(차이는 해당 주 배송비 합계).

## 기간 계산
- 오늘 날짜(`mcp__claude_ai__current_time` 또는 시스템 날짜) 기준 **직전 완료된 월~일 주**가 "지난주"다.
- 전주 = 지난주 −7일. 전년 동기 = 지난주 −364일(요일이 맞는 같은 주차. 예: 2026-10-19~25 ↔ 2025-10-20~26).
- 년도가 바뀌어도 데이터가 있는지 확인한다. 데이터가 없는 기간이면 보내지 말고 사용자에게 알린다.

## 절차
1. 작업 목록(TaskCreate)을 만든다: 데이터 가져오기 → 집계 → 슬랙 전송 → 검증.
2. Drive 검색은 `title contains '판매관리' and mimeType = 'application/vnd.google-apps.spreadsheet'` 형식을 쓴다(`name` 필드는 지원 안 됨).
3. 필요한 행 범위를 찾는다. 날짜 열(A)만 몇 군데 찍어 보고(예: 2000, 4000, 6000행 등) 범위를 좁힌 뒤, 해당 주의 `A:J`를 여유를 두고 읽는다. 날짜로 거르므로 범위는 넉넉해도 된다. 시트 전체를 읽지 않는다.
4. 읽은 값을 CSV로 옮겨 쓴다(열: date,order,channel,category,product,qty,unit,pay,ship, 쉼표 제거). 파일은 Write로 만들고 집계 스크립트도 Write로 만든 뒤 `python3 -I 스크립트 CSV경로`로 실행한다. 암산으로 합계를 내지 않는다.
5. 집계: 기간별 총매출(결제금액 합), 주문 수(주문번호 고유 수), 객단가(총매출/주문 수), 채널별·카테고리별 매출과 비중, 상품별 TOP 5(매출·수량), 일별 매출. 비교는 증감률(%) 포함.
6. 검증: (a) 채널 합계와 카테고리 합계가 각각 총매출과 같은지, (b) 행 수가 시트에서 읽은 날짜별 행 수와 맞는지, (c) `결제금액 = 단가×수량` 위반 행 수, (d) 가능하면 `대시보드` 탭의 정의(총 매출, 객단가)와 방식이 같은지 확인한다.
7. 슬랙: 채널 최근 메시지를 읽어 중복 확인 → 헤더 한 줄 전송 → 반환된 `message_ts`를 `thread_ts`로 리포트 전송.
8. 마무리 답변: 결과 한두 문장(총매출과 비교 증감), 배송비 기준 처리 안내, 시트 선택 사실을 짧게. 단계별 설명을 원하는 사용자라면 한 번에 모든 걸 늘어놓지 말고 필요한 만큼만 전한다.

## 스레드 리포트 형식 (슬랙 마크다운)
```
**📊 주간 매출 리포트 (YYYY-MM-DD ~ MM-DD)**
_기준: 결제금액 합계(배송비 별도, 매출에 미포함) · 주문 수는 주문번호 기준 · 출처: 구글 시트 '판매관리' 판매내역_

**1. 핵심 지표**  표: 지표 | 지난주 | 전주 | 전주 대비 | 전년 동기 | 전년 동기 대비
**2. 판매채널별 매출**  표: 채널 | 매출 | 비중 | 전주 대비 | 전년 동기 대비
**3. 카테고리별 매출**  표: 카테고리 | 매출 | 비중 | 전주 대비 | 전년 동기 대비
**4. 상품별 TOP 5 (매출 기준)**  표: 순위 | 상품명 | 매출 | 수량 | 비중
_참고: 일별 최고/최저 매출_
```
- 선택하지 않은 항목은 뺀다. 숫자는 `4,323,900원`, 증감은 `+11.2%`/`-6.3%` 형식. 표의 파이프(`|`)는 이스케이프하지 않는다.
- 해석 문장은 사실(증감, 비중)만 쓰고 원인을 단정하지 않는다.

## 주의
- 슬랙 전송은 사용자가 요청한 채널에만 한다. 외부 공유(Slack Connect) 채널에는 보낼 수 없다.
- 시트를 수정하지 않는다(읽기 전용).
- 정기 실행을 원하면 예약 작업으로 만들 수 있다고 제안하되, 요청이 없으면 만들지 않는다.
